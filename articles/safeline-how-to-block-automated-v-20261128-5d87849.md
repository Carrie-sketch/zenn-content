こうかいサイトには、じどうで URL をたどり、パラメーターをかえながら、ぜいじゃくせいをさがすリクエストがとどきます。SafeLine WAF をどうにゅうするときのめあては、あやしいアクセスをへらしつつ、ふだんのブラウザー、かんしサービス、API クライアントをうごかしつづけることです。

スキャナーが AI をつかっているかどうかより、なにを、どのじゅんばんで、どれくらいおくっているかをみましょう。この記事では、ログでたしかめながら、だんかいてきにトラフィックを SafeLine へとおすてじゅんをまとめます。

## 1. まずアクセスログで、ふせぎたいものをわける

せっていをかえるまえに、いまのアクセスログをみます。かんけいのないパスへのれんぞくアクセス、かんりページをさがすリクエスト、ディレクトリトラバーサルをねらうもじれつ、クエリへのインジェクションなどがてがかりです。

- リクエストされたパス
- タイムスタンプ
- レスポンスのステータス
- アクセスもとの IP アドレス
- あるじかんはばでのリクエストすう

これらをアプリのエラーやログインのログとつきあわせます。User-Agent がみなれない、というだけではブロックのこんきょとしてよわすぎます。User-Agent はかえられますし、せいじょうなツールもありふれたなまえをつかいます。

ペイロードをとめたいのか、アクセスのりょうをおさえたいのか、あやしいページめぐりにたいおうしたいのかをわけてください。もしこうげきがとおったうたがいがあれば、ログをほぞんし、アプリをしらべます。そのあとのアクセスをとめても、すでにはいりこまれていないとはいえません。

## 2. ホストと、もとにもどすてじゅんをそろえる

SafeLine は、アプリのまえで HTTP トラフィックをフィルタリングし、かんしするセルフホストの WAF です。Web こうげきへのぼうぎょ、IP ごとのレートせいげん、アクセスせいぎょ、CAPTCHA にたいおうしています。

どうにゅうまえに、Linux x86_64 のホストで、つぎのさいていじょうけんをたしかめます。

- Docker 20.10.14 いこう
- Docker Compose 2.0.0 いこう
- CPU 1 コアいじょう
- メモリー 1 GB いじょう
- ディスクのあき 5 GB いじょう
- CPU の SSSE3 たいおう

これはさいていじょうけんであり、あなたのサイトのトラフィックをさばけるというほしょうではありません。どうにゅうじには、[こうしきドキュメント](https://docs.waf.chaitin.com/en/home)からインストールてじゅんとチェックコマンドをたしかめてください。

いまの DNS、オリジンのアドレス、もとにもどすためのそうさもひかえておきます。きりかえは、たんとうしゃがすぐにサイトをテストできるじかんにおこないます。

## 3. インストールしてダッシュボードへはいる

こうしきのじどうデプロイてじゅんにそってインストールします。インストーラーには root けんげんがひつようなので、じっこうまえにてじゅんをよんでください。

ダッシュボードのアドレスは `https://<ip>:9443` です。`<ip>` を SafeLine ホストの IP アドレスにおきかえます。かんりしゃのログインじょうほうは、つぎのコマンドでとりだします。

```bash
docker exec safeline-mgt resetadmin
```

かえってきたじょうほうでログインします。ダッシュボードへアクセスできるひととネットワークは、しんらいできるはんいにしぼります。パスワードをチケット、スクリーンショット、きょうゆうするコマンドログにのこさないようにします。

## 4. アプリをとうろくし、こうかいトラフィックをとおす

ダッシュボードで **Applications** をひらき、**Add Application** をえらびます。アプリのドメイン、SafeLine がうけつけるポート、もとのアプリのアップストリームアドレスをせっていします。HTTPS のアプリでは SSL のオプションをえらびます。そのあと、こうかいドメインの DNS を SafeLine サーバーの IP アドレスへむけます。

SafeLine は HTTP/HTTPS のリバースプロキシとしてうごき、うけいれたリクエストをアップストリームへおくります。アップストリームには、オリジンへとどくアドレスをつかってください。DNS をきりかえたこうかいドメインをそのままつかうと、SafeLine じしんにもどるけいろになるおそれがあります。

オリジンへちょくせつアクセスして、WAF をうかいできないかもチェックします。オリジンへのアクセスをしぼるまえには、かんしやれんけいサービスへのえいきょうをたしかめてください。

## 5. ふだんのそうさと、こうげきのブロックをつきあわせる

まずトップページだけでなく、ログイン、けんさく、フォームそうしん、だいじな API のながれをテストします。がめんがひらくことにくわえて、アプリにひつようなリクエストがとどいていることもみます。

つぎに、じぶんがほゆうし、テストをきょかされているアプリにだけ、せいぎょされたこうげきテストをおこないます。こうしきのアプリせっていガイドには、インジェクションとトラバーサルのテストれいがあります。

ブロックページがでたら、ダッシュボードのこうげきリストから **detail** をひらきます。テストじこく、イベントのないよう、オリジンのログをつきあわせ、どのリクエストがとまったのかをたしかめます。

せいじょうなそうさがとまったときも、まずイベントのないようをみます。しっている IP アドレスだからというりゆうだけで、ひろいれいがいをつくらないようにしてください。

## 6. レートせいげんと CAPTCHA をすこしずつためす

こうげきペイロードがくりかえされるなら、まずこうげきけんさのけっかをみます。リクエストのりょうがもんだいなら IP ごとのレートせいげん、あやしいブラウザーそうさなら CAPTCHA のてきようをけんとうします。

しきいちやせっていこうもくは、ここでかってにきめうちしません。つうじょうじのログをもとに、ダッシュボードとドキュメントでつかえるせっていをたしかめ、えいきょうをテストしてからひろげます。

たとえば、しゃないネットワークでは、おおぜいのひとがひとつの IP アドレスをつかうことがあります。また、API クライアントやかんしサービスは、ブラウザーむけの CAPTCHA をこなせないことがあります。ぶんさんしたスキャナーは IP ごとのしきいちをこえないこともあるため、アクセスすうがすくないだけであんぜんとはいえません。

### みじかいしっぱいれい：CAPTCHA でかんしがとまる

たとえば、サイトぜんたいに CAPTCHA をてきようしたあと、かんしサービスがページをよめなくなり、アラートがでるケースをかんがえます。ブラウザーではひらけても、じどうクライアントではうごかないことがあります。

このばあいは、かんしのリクエストとイベントをつきあわせ、CAPTCHA がげんいんかをたしかめます。そのうえで、えいきょうのあるせっていをもどし、てきようするはんいをみなおしてさいテストします。かんしと API をさいしょのテストにふくめておけば、こうしたしっぱいをはやくみつけられます。

## 7. スキャンのけいぞくと、しんにゅうをわけてみる

きりかえごは、ブロックイベントだけでなく、アプリのエラー、レスポンスじかん、ログインやこうにゅうなどのだいじなながれをくらべます。あやしいリクエストが、まだオリジンへとどいていないかもみてください。

スキャンがつづくときは、WAF でとまっているのか、べつのけいろからオリジンへとどいているのか、こうげきペイロードをふくまずけんさをとおっているのかをわけます。

ひとつのテストをブロックできたことは、そのけいろの、そのリクエストがとまったことをしめします。すべてのぜいじゃくせいをふさいだことにはなりません。こうげきログをてがかりに、こうかいしているソフトウェアのバージョン、ふようなエンドポイント、パッチのじょうたいをみなおします。しんにゅうのちょうこうがあれば、ちょうさやにんしょうじょうほうのこうしんもすすめてください。
