API のトークンがもれると、ただしい HTTPS リクエストが、データをぬすむためのいりぐちになります。せっていファイルやログからえたトークンをつかえば、こうげきしゃは、いつものエンドポイントにアクセスできます。SQL インジェクションのようなペイロードがなくても、ひがいはおこります。

こうかい API を、もれたクレデンシャルのあくようからまもるには、トークンのしっこう、アプリのアクセスせいぎょ、トラフィックのせいぎょをくみあわせます。SafeLine WAF は API のまえで HTTP トラフィックをフィルタリングし、かんしするためにつかいます。トークンをむこうにするはんだんとしくみは、トークンをはっこう・けんしょうするシステムにもちます。

## 1. トークンで「なにができるか」をしらべる

まず API キー、Bearer トークン、セッション Cookie、サービスようクレデンシャルをたなおります。それぞれについて、つぎをかくにんしてください。

- だれがつかっているか
- いつまでつかえるか
- どの API とデータにアクセスできるか
- どこでしっこう・ローテーションできるか

とくに、エクスポートやかんりそうさができるトークンは、せまいはんいのよみとりようトークンよりも、はやいふうじこめがひつようです。

みなれないネットワーク、ふだんとちがうエンドポイントのよびだしじゅん、リクエストのきゅうぞうもチェックします。ただし、これらはちょうさのてがかりです。それだけであくようとだんていしないでください。

## 2. もれがわかったら、WAF のちょうせいよりさきにしっこうする

ろうえいがかくにんできたクレデンシャルは、にんしょうシステムでしっこうするか、ローテーションします。あわせて、すでにできているセッションや、そのトークンからはっこうされたべつのトークンが、まだつかえないかをしらべます。

せいきのクライアントにはあたらしいクレデンシャルをはいふし、もれたせっていファイルやログもなおします。インシデントのチケットには、ひみつそのものをはりつけないでください。じこく、リクエスト ID、ルート、レスポンスコード、ひみつではないクレデンシャルの ID をのこします。

Authorization ヘッダーや URL のトークンがログにのこるなら、ログへのアクセスをせいげんし、そのきろくほうほうをなおしてください。

### みじかいしっぱいれい

たとえば、もれたトークンをそのままにして、ひとつの IP だけをブロックしたとします。こうげきしゃがべつの IP からおなじトークンをおくると、アプリはそれをうけつけ、データをかえしてしまいます。IP のブロックだけでは、トークンのあくようをふうじこめたことにはなりません。

## 3. SafeLine をおくホストをよういする

SafeLine はセルフホストの WAF で、アプリのまえにリバースプロキシとしておくこうせいがドキュメントでしめされています。

どうにゅうまえに、x86_64 Linux、Docker 20.10.14 いこう、Docker Compose 2.0.0 いこう、CPU 1 コアいじょう、メモリ 1 GB いじょう、ディスク 5 GB いじょうをかくにんします。CPU のめいれいセットのようけんも、こうしきドキュメントでチェックしてください。

こうしきのてじゅんでインストールしたら、ダッシュボードを `https://<ip>:9443` でひらきます。かんりアクセスは、そしきのかんりネットワークのルールにあわせてせいげんします。インストールでえたひみつを、きょうゆうログやチケットにのこさないようにします。

## 4. API をとうろくし、つうしんけいろをたしかめる

コンソールで `Applications` から `Add Application` をひらき、API のドメイン、SafeLine がうけつけるポート、API サーバーのアップストリームアドレスをせっていします。HTTPS では SSL のオプションをえらびます。

せっていをよういしてから、API ドメインの DNS レコードを SafeLine サーバーへむけます。きりかえごは、せいきのクライアントでつぎをたしかめます。

- にんしょうがとおる
- いつものリクエストボディをおくれる
- きたいするレスポンスがかえる
- API のもとのサーバーへ、SafeLine をうかいしてアクセスできるけいろがない

## 5. IP のせいげんと、トークンのせいげんをくみあわせる

SafeLine では、IP ベースのレートせいげんと Web アクセスせいぎょリストがドキュメントにあります。しきいちは、せいきのクライアントのつかいかたをみてきめます。

ひとつのかいしゃのゲートウェイから、たくさんのクライアントがアクセスすることもあります。ぎゃくに、こうげきしゃはふくすうの IP にリクエストをわけられます。IP ごとのせいげんだけで、トークンごとのあくようをすべてせいぎょすることはできません。

トークンごとのクォータ、オブジェクトごとのアクセスけんげん、エクスポートなどのそうさごとのせいげんは、アプリや API のきばんでじっそうします。ここでよりどころにするドキュメントには、SafeLine のトークンごとのクォータや、もれたキーのじどうけんしゅつはしめされていません。

CAPTCHA も、API ではてきようまえにクライアントとのあいしょうをたしかめます。きかいのクライアントは、たいわしきのチャレンジをかいけつできないことがあります。

## 6. テストで、ふうじこめとフィルタリングをたしかめる

ステージングか、めいじてきにきょかされたテストじかんをつかいます。

1. しっこうしたトークンでアクセスできないことをたしかめる。
2. あたらしいトークンで、ひつようなそうさができることをたしかめる。
3. けんげんのひくいトークンで、ほかのテナントのオブジェクトをよめないことをたしかめる。
4. こうしきガイドのテストようリクエストをつかい、コンソールのこうげきリストとしょうさいをみる。
5. アプリのにんしょうログ、アクセスログと、じこくやリクエスト ID をつきあわせる。

インジェクションをブロックできたことは、そのリクエストへのフィルタリングをたしかめたけっかです。ぬすまれたゆうこうなトークンのさいりようもとめられる、というしょうめいにはなりません。

レスポンスがせいじょうでも、データがとれすぎるなら、テナントのさかい、オブジェクトのもちぬし、ページネーション、エクスポートけんげんをしらべます。にんしょうにせいこうしたことと、すべてのデータをよめることはべつです。

ふうじこめのチェックでは、もれたクレデンシャルとセッションがつかえないこと、もれたばしょがなおったこと、あたらしいクレデンシャルがうごくこと、ふせいなアクセスけいろがふさがったことをたしかめます。そのうえで、えいきょうしたじかんたいのログをしらべ、どのデータまでアクセスされたかをつめていきます。
