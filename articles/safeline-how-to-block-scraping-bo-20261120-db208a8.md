スクレイピングボットネットは、ページをあつめながら、ふるいプラグインのありかもさぐります。プラグインのディレクトリ、バージョンをしめすファイル、ログインページなどへのアクセスが、そのてがかりです。よわいコンポーネントがみつかれば、つぎにこうげきがくるおそれがあります。

ここでは SafeLine WAF をつかい、ふつうのクロールとあやしいアクセスをみわけながら、サービスへのえいきょうをおさえてたいしょするてじゅんをまとめます。WAF をおくだけで、プラグインのぜいじゃくせいがなおるわけではありません。アプリのメンテナンスとログのかくにんを、セットですすめましょう。

## 1. まずプラグインとアクセスさきをたしかめる

アプリでつかっているプラグインについて、なまえ、バージョン、サポートのじょうたい、そとからアクセスできる URL をメモします。つかわないものはとりのぞき、ぜいじゃくせいのあるものはアップデートします。SafeLine がプラグインのリストやふるいバージョンをじどうであらいだす、とはかんがえないでください。

つぎに Web アクセスログをみます。プラグインのパス、メタデータのファイル、かんりページ、そもそもないはずのパスへのアクセスをひろい、じこく、パス、HTTP ステータス、アクセスもとの IP アドレスをならべます。

むかんけいなプラグインのパスをつぎつぎにたどるうごきは、さぐりのてがかりです。ただし、200 がかえってきただけで、プラグインがあるとはいえません。ない URL にもトップページをかえすアプリがあるためです。かならず、ないとわかっているパスのレスポンスと、ボディやページのないようをくらべます。

## 2. SafeLine をおくホストをチェックする

SafeLine は、アプリのまえで HTTP/HTTPS トラフィックをうけるセルフホストの WAF です。Web こうげきへのぼうぎょ、IP ごとのレートせいげん、アクセスせいぎょ、CAPTCHA チャレンジをそなえています。

インストールにあたっては Linux、Docker 20.10.14 いこう、Docker Compose 2.0.0 いこうがひつようです。リソースのめやすは CPU 1 コア、メモリ 1 GB、ディスク 5 GB いじょうです。ARM へのデプロイには Pro ライセンスがひつようとされているため、ホストをえらぶまえにアーキテクチャもかくにんします。

```bash
uname -m
docker version
docker compose version
free -h
df -h
```

これらにくわえて、インストールガイドにある CPU のごかんせいチェックもおこないます。てじゅんは https://docs.waf.chaitin.com/en/home からたどれます。じどうインストールには root けんげんがひつようなので、じっこうまえにてじゅんをよんでください。

## 3. かんりがめんをひらき、アプリをとうろくする

インストールできたら、`https://<ip>:9443` をひらきます。しょきのかんりしゃじょうほうは、つぎのコマンドでしゅとくします。

```bash
docker exec safeline-mgt resetadmin
```

ひょうじされたにんしょうじょうほうはあんぜんにほかんし、かんりがめんへのアクセスは、そしきのかんりネットワークのルールにあわせてせいげんします。

コンソールの **Applications** から **Add Application** をえらび、ドメイン、SafeLine がうけつけるポート、てんそうさきのアプリのアドレスをせっていします。HTTPS のアプリでは SSL をゆうこうにします。そのうえで、アプリのドメインが SafeLine サーバーをさすようにきりかえます。

きりかえたら、ページのえつらん、ログイン、フォームそうしん、ひつような API リクエストをチェックします。べつの IP アドレスやホストめいからオリジンへちょくせつアクセスできないかもたしかめ、ひつようにおうじてネットワークやホスティングのせいぎょでせいげんします。ここがあいたままだと、SafeLine をとおらないアクセスがのこります。

## 4. ログにあわせてせいげんをえらぶ

ひとつの IP からリクエストがおおくきているなら、IP ごとのレートせいげんをけんとうします。ただし、ボットネットはアクセスもとをぶんさんできます。IP ごとではしきいちをこえなくても、おなじじかんたいにおなじようなプラグインのパスをさぐっていないか、まとめてみることがたいせつです。

ブラウザーむけのページでボットによるひがいがでているなら、CAPTCHA チャレンジもせんたくしになります。てきようまえに、ふつうのユーザーがそうさできるか、ひつようなじどうアクセスをさまたげないかをテストします。システムどうしでつかう API に、ブラウザーむけのチャレンジをそのままてきようしないでください。

プラグインのディレクトリへのアクセスだけをりゆうに、すべてをブロックするのはさけます。そのパスが CSS や JavaScript などのひつようなファイルをかえしていないか、れんぞくしたれっきょやこうげきらしいリクエストをともなっていないかをみて、たいしょをきめます。

### みじかいしっぱいれい

あるサイトで、プラグインらしいパスに 200 がかえったため、たんとうしゃがそのパスへのアクセスをまとめてブロックした、とします。ところが、200 のなかみは、ない URL にもかえるふつうのページでした。さらに、おなじディレクトリにあるひつようなファイルまでとまり、ページのひょうじがくずれました。

このようなケースでは、まずせいげんをみなおし、ないパスとのレスポンスひかくと、ひつようなファイルのチェックをやりなおします。ステータスだけでなく、なにがかえったかをみることが、あやまったブロックをへらします。

## 5. ブロックとオリジンのログをつきあわせる

じぶんがかんりする、またはテストのきょかをえたアプリで、アプリせっていガイドのテストをおこないます。ブロックページをかくにんし、コンソールのこうげきリストとしょうさいをみます。

そのあと、じっさいのあやしいアクセスをオリジンのログとつきあわせます。アプリまでとどいたか、ひみつにすべきファイルがかえったかをたしかめてください。ひとつのリクエストがブロックされたことと、サイトがあんぜんなことは、べつのかくにんです。

## 6. すでにしんにゅうされていないかをしらべる

あやしいアクセスのまえあとに、ファイルのへんこう、みおぼえのないかんりしゃアカウント、ふしんなサーバープロセスがないかをしらべます。しんにゅうのてがかりがあれば、かんれんログをほぜんし、ホストをちょうさします。

あとからアクセスをブロックしても、すでにおかれた Web シェルや、ぬすまれたにんしょうじょうほうはなくなりません。もんだいのあるプラグインのアップデートやじょきょにくわえ、ふっきゅうできたことまでかくにんします。うんようでは、アクセスのせいぎょ、アプリのしゅうせい、しんにゅうのちょうさを、それぞれすすめてください。
