AIでつくられたようにみえるペイロードが、すこしずつかたちをかえてとどく。ログインへのアクセスもふえ、ログをひとつずつおうだけではおいつかない。そんなとき、まずきめたいのは「AIかどうか」ではなく、「どこをねらい、なにをおこそうとしているか」です。

「how to defend against ai generated attack payloads」というテーマを、SafeLine WAFのどうにゅうと、にちじょうのチェックにおとしこんでみます。

SafeLineは、セルフホストでHTTP/SトラフィックをリバースプロキシとしてフィルタリングするWAFです。よくあるWebへのこうげきにたいするぼうぎょ、IPベースのレートリミット、CAPTCHAがドキュメントであんないされています。ただし、ペイロードをAIがつくったかどうかをみわけるきのうは、ここでさんしょうするドキュメントからはかくにんできません。

## 1. ペイロードのことばより、アクセスのうごきをみる

まず、いまつかっているプロキシとアプリのログから、あやしいリクエストをあつめます。じこく、HTTPメソッド、パス、ステータスコード、アクセスもとのIP、かんれんするパラメーターをそろえてください。パスワードやトークン、こじんにかかわるデータは、きょうゆうするまえにマスクします。

チェックするのは、たとえばつぎのようなうごきです。

- おなじパラメーターに、かきかたをかえたSQLインジェクションらしきリクエストがつづく。
- アプリにないパスや、かんけいのないパスへのアクセスがひろがる。
- ログインのしっぱいが、みじかいあいだにかたまっている。

これらをすべておなじたいさくであつかわないことがポイントです。インジェクションにはリクエストのけんさとアプリのしゅうせいが、ログインのらんようにはにんしょうまわりのたいさくもひつようです。

あわせて、ふだんのログイン、けんさく、こうにゅう、APIアクセスのレスポンスとせいこうじょうけんをひかえます。「あやしいアクセスをとめた」だけでなく、「いつものそうさがとおる」こともごうかくじょうけんにしてください。

## 2. インストールまえにホストをチェックする

こうしきガイドのようけんは、Linux、Docker 20.10.14いこう、Docker Compose 2.0.0いこうです。さいしょうリソースはCPU 1コア、メモリー1 GB、ディスク5 GBです。

```bash
uname -m
docker version
docker compose version
free -h
df -h
```

`uname -m`ではアーキテクチャーもかくにんします。ガイドでは、ARMでのはいちはProライセンスがひつようで、Personal Editionにはたいおうしないとされています。

さいしょうようけんをみたしていても、ほんばんのトラフィックをさばけるとはかぎりません。じぶんたちのアクセスりょうとテストで、ひつようなリソースをみきわめます。

## 3. SafeLineをはいちし、かんりアクセスをととのえる

[こうしきドキュメント](https://docs.waf.chaitin.com/en/home)からインストールガイドをひらき、じどうデプロイのてじゅんにそってすすめます。このてじゅんにはrootけんげんがひつようです。インストーラーは、そしきのソフトウェアどうにゅうルールにそって、じっこうまえになかみをチェックしてください。

ダッシュボードは `https://<ip>:9443` です。かんりしゃのにんしょうじょうほうは、つぎのコマンドでしゅとくします。

```bash
docker exec safeline-mgt resetadmin
```

ひょうじされたじょうほうは、そしきでみとめられたシークレットほかんさきへいれます。かんりアクセスも、ひつようなかんりしゃにしぼってください。

## 4. アプリをとうろくし、つうしんけいろをたしかめる

コンソールの `Applications` から `Add Application` をえらび、アプリのドメイン、SafeLineがまちうけるポート、アップストリームのアドレスをせっていします。HTTPSでは、ガイドにそってSSLオプションをえらびます。

ほんばんDNSをきりかえるまえに、SafeLineからアップストリームへとどくことと、もとのけいろにもどすてじゅんをかくにんします。そのうえで、アプリのドメインがSafeLineサーバーのIPをむくようにします。

きりかえたあとは、ドメイン、HTTPS、ログインなどのじゅうようなそうさをチェックします。オリジンへちょくせつアクセスできないかもたしかめてください。こうせいじょうかのうなら、オリジンへのこうかいアクセスをせいげんし、けんさをうかいするけいろをふさぎます。

## 5. ブロックと、ふつうのそうさをセットでテストする

きょかされたテストかんきょう、またはしょうにんずみのほんばんテストじかんでじっしします。アプリせっていのガイドには、SQLインジェクション、XSS、パストラバーサル、コードインジェクション、XXEのテストリクエストがあります。

テストごとに、つぎのみっつをつきあわせます。

1. クライアントにかえったレスポンス。
2. SafeLineのこうげきリストと `detail` のないよう。
3. アップストリームのアクセスログとアプリのログ。

ブロックページだけでけっかをきめず、どのリクエストをとめたのかをかくにんします。また、アップストリームにログがないことをこんきょにするなら、さきにログがもれなくきろくされることをたしかめておきます。

ふつうのリクエストもおなじようにながしてください。もしひつようなそうさがとまったら、エンドポイントとリクエストのなかみをしらべてから、ぼうぎょせっていのへんこうをけんとうします。

### みじかいしっぱいれい：ブロックできても、うかいされる

たとえば、テストでSQLインジェクションがブロックされたため、どうにゅうかんりょうとしたケースをかんがえます。しかし、オリジンのこうかいIPへちょくせつアクセスできるままでした。そのけいろではSafeLineをとおらず、テストしたぼうぎょははたらきません。

このしっぱいからひつようになるのは、ペイロードのバリエーションをふやすことだけではありません。DNSのむきさきと、オリジンへのアクセスせいげんをチェックし、そうていしたけいろでテストをやりなおすことです。

## 6. アクセスりょうへのたいさくをくわえ、せいこうのこんせきをおう

IPベースのレートリミットとCAPTCHAは、トラフィックのとくせいにあわせてけんとうします。おなじIPをおおくのりようしゃがつかうかんきょうでは、IPだけのせいげんがふつうのアクセスにもえいきょうしえます。CAPTCHAも、ブラウザーでのそうさとマシンどうしのAPIではあつかいがことなるため、ひろくてきようするまえにテストします。

アクセスもとがぶんさんしているばあいは、IPだけにたよれません。アプリがわでも、にんしょうのきょうか、アカウントごとのらんようチェック、エンドポイントごとのけんげんチェックをくみあわせます。

あやしいリクエストがせいこうしたようにみえたら、アプリのエラー、そうていがいのデータアクセス、あたらしいファイル、ふしんなプロセスのうごきをつきあわせます。しょうこをほぜんし、もとのぜいじゃくせいをしゅうせいしてください。WAFをはいちしたことだけでは、すでにしんにゅうされたサーバーがあんぜんになったとはいえません。

ペイロードがかわりつづけても、エンドポイントとねらわれたうごきでまとめれば、しらべるべきたいしょうをしぼれます。せいこうしたアクセスのこんせきをゆうせんし、たいさくのたびに、ひつようなそうさがとおることまでたしかめましょう。
