WAFのまえだんでアクセスをしぼりたいとき、さいしょにきめるのは「パスワードをしっているひとをとおす」のか、「アクセスしたひとがだれなのかをたしかめる」のか、ということです。

`how to enable identity authentication on a waf application` をしらべてSafeLineにたどりついたばあいも、このちがいをおさえるところからはじめましょう。SafeLineのAuthentication Challengeについて、こうしきドキュメントがせつめいしているのは、パスワードのにゅうりょくをもとめ、にゅうりょくしないアクセスをブロックするしくみです。ひとりずつのアカウント、IdPとのれんけい、SSOについては、ここでさんしょうするしりょうではかくにんできません。

この記事では、そのパスワードによるチャレンジをつかうために、うんようたんとうしゃがたしかめることをじゅんにまとめます。

## 1. とおしたいアクセスをことばにする

まず、たいしょうのアプリと、アクセスをみとめるじょうけんをメモします。「パスワードをしっていればよい」というようけんなら、Authentication Challengeのせつめいとてらしあわせてけんとうできます。

いっぽう、「たいしょくしたひとだけをとめたい」「アクセスしたひとのなまえをとくていしたい」「ひとによってつかえるきのうをかえたい」というようけんは、べつのチェックこうもくにしてください。パスワードをとおったことだけでは、だれがアクセスしたかのしょうめいにはなりません。

ここでのチェックは、ようけんがパスワードによるアクセスせいげんなのか、ひとりずつのほんにんかくにんなのかを、チームでくべつできていることです。

## 2. SafeLineのどうさかんきょうをたしかめる

あたらしくどうにゅうするばあいは、こうしきのインストールガイドとサーバーをてらしあわせます。しりょうにあるじょうけんは、Linux、Docker 20.10.14いこう、Docker Compose 2.0.0いこう、CPU 1コアいじょう、メモリー1 GBいじょう、ディスク5 GBいじょうです。CPUのssse3についてのじょうけんもかくにんしてください。

ARMについては、ガイドにProライセンスがひつようで、Personal Editionはたいおうしないときさいされています。サーバーのアーキテクチャも、どうにゅうまえのチェックにふくめます。

すでにSafeLineがうごいているなら、まずかんりコンソールをひらけることをたしかめます。

## 3. かんりコンソールにはいる

ブラウザーで `https://<ip>:9443` をひらきます。`<ip>` はSafeLineサーバーのIPアドレスにおきかえてください。

はじめてのセットアップでかんりしゃのにんしょうじょうほうをえるてじゅんとして、インストールガイドにはつぎのコマンドがしめされています。

```bash
docker exec safeline-mgt resetadmin
```

これはSafeLineをかんりするためのじょうほうです。アプリのりようしゃににゅうりょくしてもらうチャレンジのパスワードとは、わけてあつかってください。かんりしゃのパスワードを、そのままりようしゃへくばるというはんだんはしないようにします。

## 4. アプリをつなぎ、ふつうのアクセスをたしかめる

Web Admin Consoleで「Applications」をひらき、「Add Application」をえらびます。こうしきガイドがしめすせっていこうもくは、つぎの3つです。

- Domain：アプリのドメイン、ホストめい、またはIPアドレス。
- Port：SafeLineがまちうけるポート。たとえば80や443。HTTPSのアプリではSSLのオプションをえらびます。
- Upstream：SafeLineがリクエストをてんそうする、じっさいのアプリのアドレス。

せっていしたら、アプリのドメインがSafeLineサーバーのIPアドレスにかいけつされるようにします。このこうせいでは、SafeLineがHTTP/HTTPSのリバースプロキシとしてはたらきます。

チャレンジをいれるまえに、ページのひょうじや、ふだんつかうそうさをたしかめてください。このじてんでアクセスできなければ、Domain、Port、Upstream、ドメインのかいけつさきをみなおします。さきにどうさのきじゅんをつくっておくと、あとでげんいんをきりわけやすくなります。

## 5. Authentication Challengeのせっていをさがす

こうしきのしょうかいでは、Authentication Challengeをゆうこうにするとパスワードがもとめられることをかくにんできます。ただし、さんしょうしりょうには、メニューのばしょ、パスワードのせっていらん、ゆうこうにするまでのクリックじゅんはありません。

そのため、ここでかくじつなクリックてじゅんをしめすことはできません。じっさいにつかっているバージョンのコンソールと、それにあうドキュメントで、つぎをかくにんしてください。

- Authentication Challengeのせっていがどこにあるか。
- どのアプリにてきようされるか。
- りようしゃむけのパスワードをどうせっていするか。

これらがはっきりしてから、テストようのアプリでゆうこうにします。てきようはんいやパスワードのあつかいがわからないまま、ほんばんのアクセスをへんこうしないことが、うんようじょうのポイントです。

## 6. べつのブラウザーでとおる・とおらないをたしかめる

かんりコンソールとはべつのブラウザーセッションをつかい、りようしゃのたちばでアクセスします。まず、ひつようなパスワードをにゅうりょくしないとアクセスがブロックされるかをたしかめます。つぎに、せっていしたパスワードをにゅうりょくして、アプリへすすめるかをたしかめます。

ページがひらくだけでチェックをおえず、ログイン、フォームそうしんなど、そのアプリでかかせないそうさもためしてください。じどうクライアントをうんようしているなら、それらのリクエストもチェックします。

セッションがどれだけつづくか、れいがいをつくれるか、ほかのしくみとれんけいできるかは、さんしょうしりょうだけではわかりません。きたいどおりにはたらくときめつけず、じっさいのけっかをきろくしましょう。

## 7. しっぱいれいからチェックをふやす

たとえば、たんとうしゃのブラウザーではアクセスできたためにテストをおえ、そのあとでじどうクライアントのしょりがすすまなくなるケースをかんがえます。これはせいひんのかくていしたどうさをしめすものではなく、テストもれのれいです。

このばあいは、チャレンジをいれるまえとあとのリクエストけっかをくらべます。ブラウザーでのせいこうだけをもとに、すべてのアクセスがつかえるとはんだんしないことがたいせつです。ほんばんへてきようするまえに、えいきょうをうけるクライアントと、へんこうをもどすてじゅんをかくにんしておきます。

さいごのうけいれチェックでは、パスワードなしのブロック、パスワードありのアクセス、アプリのしゅようなそうさ、じどうクライアントのどうさをそろえてきろくしてください。CAPTCHA Challengeはボットたいさくとしてべつにせつめいされており、Authentication Challengeとおなじものではありません。また、パスワードのチャレンジだけで、アプリがもつべきユーザーごとのけんげんまでみたせるとはんだんせず、そのようけんはべつにたしかめましょう。
