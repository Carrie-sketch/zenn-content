プロダクトのリリースびには、こうにゅうしたいユーザーと、ログインやAPIをねらうボットが、おなじエンドポイントへアクセスします。アクセスがふえたというりゆうだけで、サイトぜんたいをきびしくせいげんすると、せっかくきたユーザーまでとめてしまいます。

この記事では、というようなかたいせつめいよりも、とうじつに「なにをみて、どこをかえるか」をじゅんばんにまとめます。SafeLineは、アプリケーションのてまえでHTTP/Sトラフィックをフィルタリングする、セルフホストのWAFです。ウェブこうげきへのぼうぎょ、IPベースのレートせいげん、CAPTCHAを、アクセスのふるまいにあわせてつかいます。

## 1. まもるルートと、ふだんのようすをそろえる

まず、リリースでつかうホストめい、アプリケーションのアップストリーム、HTTPSのようけんをひかえます。ログイン、アカウントさくせい、パスワードリセット、チェックアウト、こうかいAPIを、それぞれべつのチェックたいしょうにしてください。

つぎに、いまあるモニタリングで、リクエストすう、おうとうじかん、アプリケーションエラー、ログインしっぱい、こうにゅうかんりょうのようすをきろくします。せっていをかえるひとと、ユーザーへのえいきょうをたしかめるひとも、さきにきめておきます。

アクセスすうだけでは、こうげきかどうかはわかりません。こうにゅうがのびているのか、ログインしっぱいだけがふえているのかを、アプリケーションのけっかとつきあわせることがしゅっぱつてんです。

## 2. ホストのじょうけんと、よゆうをチェックする

インストールガイドでは、Linux、Docker 20.10.14いこう、Docker Compose 2.0.0いこうがようけんです。さいしょうリソースは、CPU 1コア、メモリ1 GB、ディスク5 GBです。ただし、これはリリースじのアクセスをさばけるほしょうではありません。じぶんたちのワークロードで、ふかをかけてたしかめます。

```bash
uname -m
docker version
docker compose version
free -h
df -h
```

アーキテクチャとCPUのめいれいセットも、インストールガイドとてらしあわせます。ARMではProライセンスがひつようで、Personal Editionはサポートされません。ホストからアップストリームへつながること、かんりしゃがアクセスできることも、どうにゅうまえにたしかめてください。

## 3. インストールして、かんりアクセスをととのえる

こうしきガイドのじどうデプロイてじゅんをかくにんし、インストーラーをレビューしてから、たいしょうホストでじっこうします。このてじゅんにはrootけんげんがひつようです。Docker Composeをつかうしゅどうデプロイのてじゅんもあります。

ダッシュボードは `https://<ip>:9443` でひらきます。かんりしゃのにんしょうじょうほうは、つぎのコマンドでしゅとくします。

```bash
docker exec safeline-mgt resetadmin
```

にんしょうじょうほうはあんぜんにほかんし、かんりアクセスはうんようたんとうしゃにしぼります。これはデプロイじのうんようほうしんとしておこないます。

## 4. アプリケーションをつなぎ、ユーザーのどうせんをためす

コンソールの **Applications** から **Add Application** をひらき、ドメイン、リッスンポート、アップストリームのアドレスをせっていします。HTTPSでは、ガイドのSSLオプションにしたがいます。そのあと、アプリケーションのドメインがSafeLineサーバーのIPアドレスへむくようにします。

SafeLineはリバースプロキシとしてリクエストをうけ、きょかしたトラフィックをアップストリームへてんそうします。せっていごは、つぎをじっさいにためしてください。

- DNSがいとしたアドレスをかえす。
- HTTPSとリダイレクトがただしくうごく。
- ログインからチェックアウトまでかんりょうできる。
- APIのステータスとレスポンスがそうていどおりになる。
- べつのホストめいやIPアドレスで、オリジンへちょくせつアクセスできないかをたしかめる。

インフラがたいおうできるなら、ひつようなうんようアクセスをのこしつつ、オリジンへのアクセスをいとしたプロキシけいろにしぼります。ルーティングをもとへもどすてじゅんも、きりかえまえにきろくしてください。

## 5. こうげきのふるまいごとに、たいおうをえらぶ

まずステージングなど、じぶんたちがテストをきょかされたアプリケーションで、ガイドにあるSQLインジェクション、XSS、パストラバーサルのテストをおこないます。そうていしたブロックをたしかめ、コンソールのこうげきリストとリクエストしょうさいをみます。

リリースちゅうは、つぎのようにきりわけます。

1. あやしいペイロードがあるときは、ねらわれたルートとリクエストしょうさいをしらべます。アプリケーションのしゅうせいがひつようかもかくにんします。ブロックできたことだけで、しんがいがないとははんだんしません。
2. おなじそうしんもとが、おもいページやログインをくりかえしたたくときは、IPベースのレートせいげんをけんとうします。しきいちは、じっさいのせいじょうなアクセスをもとにきめます。
3. ブラウザーのじどうそうさがうたがわしいときは、CAPTCHAをけんとうします。さきにユーザーのどうせんをテストし、APIクライアントはべつにひょうかします。たいわがひつようなチャレンジは、きかいどうしのつうしんをさまたげることがあります。

### しっぱいれい：ログインのしっぱいだけをみて、しぼりすぎる

たとえば、ログインしっぱいがふえたため、サイトぜんたいにきびしいIPせいげんをかけたとします。すると、おなじネットワークをつかうユーザーがまとめてせいげんされ、チェックアウトまでへることがあります。これはそうていれいですが、きょうゆうIPをかんがえずにしきいちをきめるとおきうるしっぱいです。

へんこうするまえに、たいしょうルート、しっぱいのわりあい、せいじょうなユーザーのリクエストひんどをみます。へんこうごは、ログインせいこうとこうにゅうかんりょうもチェックし、えいきょうがあればもどせるようにします。

## 6. WAFとにんしょうログをつきあわせ、しゅうそくをはんだんする

ぬすまれたにんしょうじょうほうをつかうアクセスは、たくさんのIPにぶんさんし、IPごとのしきいちをこえないことがあります。WAFのかんそくだけでなく、にんしょうログ、えいきょうをうけたアカウント、セッションのうごきをつきあわせてください。

ログインせいこうごにふしんなアカウントへんこうがあれば、セッションをしらべ、じぶんたちのアカウントふっきゅうてじゅんをつかいます。WAFだけで、にんしょうじょうほうのりゅうしゅつやアカウントへのアクセスのうむはかくていできません。

アクセスがおちついても、すぐにしゅうりょうとはしません。ほかんポリシーにしたがい、WAFのリクエストしょうさい、アプリケーションログ、にんしょうイベント、じこく、せっていへんこうをのこします。あやしいリクエストがアプリケーションへとどいたか、アカウントやデータにえいきょうがあったかまでたしかめて、たいおうをとじます。
