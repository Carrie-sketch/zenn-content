WAF をセットアップしたら、ふだんのページがひらけること、テスト URL がブロックされること、そのリクエストにあうイベントがコンソールにあることをセットでたしかめます。エラーページがでた、というだけでは、WAF がブロックしたとはいえません。

このガイドでは、SafeLine のドキュメントにあるコードインジェクションのテスト URL をつかいます。SafeLine は、HTTP トラフィックをフィルタリングしてモニタリングするセルフホストの WAF です。HTTP/HTTPS のリバースプロキシとして、うけいれたリクエストをアップストリームへわたします。

## 1. テストするアプリとメモをそろえる

じぶんでかんりするアプリ、またはテストのきょかがあるアプリをつかってください。できればステージングでおこないます。

まず、いつもどおりひらけるページをひとつきめます。つぎのことをメモしておくと、あとでレスポンスとイベントをつきあわせやすくなります。

- アプリのホストネーム
- テストをおこなうじこくとタイムゾーン
- ふだんの HTTP ステータスと、ページをみわけられるテキスト
- アップストリームのアドレス

テスト URL には PHP のかんすうめいがふくまれます。クエリをじっこうするエンドポイントをつくってはいけません。ぜいじゃくなアプリにとどいてもだいじょうぶ、とはかんがえないでください。ここでたしかめるのはフィルタリングであり、サーバーでのコードじっこうではありません。

## 2. インストールのじょうけんをチェックする

これからインストールするなら、Linux、Docker 20.10.14 いこう、Docker Compose 2.0.0 いこうをそろえます。ドキュメントにあるさいていリソースは、CPU 1 コア、メモリ 1 GB、ディスク 5 GB です。

CPU のめいれいセットとアーキテクチャにもじょうけんがあります。ARM では Pro ライセンスがひつようとされているため、つかうホストがじょうけんにあうか、さきにドキュメントでチェックします。すいしょうされるじどうインストールには root のけんげんがひつようです。

セットアップのさいは、[SafeLine のドキュメント](https://docs.waf.chaitin.com/en/home)からインストールガイドをひらき、そのてじゅんにそってすすめてください。

## 3. コンソールでアプリをセットアップする

ダッシュボードのアドレスは `https://<ip>:9443` です。`<ip>` を SafeLine サーバーの IP アドレスにおきかえてひらきます。かんりしゃのログインじょうほうは、インストールガイドにある `docker exec safeline-mgt resetadmin` でしゅとくできます。

コンソールの **Applications** から **Add Application** をひらき、つぎのこうもくをセットします。

- **Domain**: ブラウザーからアクセスするホストネーム
- **Port**: SafeLine がリクエストをうけるポート
- **SSL**: HTTPS のアプリならえらぶ
- **Upstream**: もとのアプリのアドレス

ホストネームのなまえかいけつが、SafeLine サーバーの IP アドレスをかえすこともたしかめます。アップストリームへちょくせつアクセスしてしまうと、ねらった WAF のけいろをテストできません。

## 4. ふだんのアクセスをきろくする

セットしたホストネームで、さきほどきめたページをひらきます。HTTP ステータスだけでなく、みおぼえのあるテキストやページのないようもたしかめてください。

ページがひらけないなら、ここでいったんとめます。なまえかいけつ、TLS、リスナーポート、アップストリームへのアクセスをチェックします。ふだんのアクセスがこわれているままでは、あとででたエラーをブロックとくべつできません。

## 5. コードインジェクションのテスト URL をおくる

ドキュメントにあるクエリはつぎのとおりです。

```text
?id=phpinfo();system('id')
```

これを、テストするアプリの HTTPS ホストネームにつなげます。たとえば、じぶんでかんりするホストが `app.example.com` なら、つぎのかたちです。

```text
https://app.example.com/?id=phpinfo();system('id')
```

`app.example.com` はかならずじぶんのテストホストにおきかえてください。ふだんのアクセスとおなじホストネームをつかい、ブラウザーからリクエストをおくります。おくった URL とじこくをメモし、SafeLine のブロックページがでるかをたしかめます。

タイムアウトや、アプリがかえしたエラーページだけでは、ブロックできたとはいえません。ブロックページがでたら、そのがめんもほぞんしておきます。

## 6. コンソールのイベントとつきあわせる

SafeLine コンソールのアタックリストをひらき、テストしたリクエストにあうイベントをさがします。**detail** からくわしいじょうほうをひらき、ひょうじされるないようを、メモしたじこくやリクエストとつきあわせてください。

さいごに、クエリをつけていないふだんのページをもういちどひらきます。テストまえとテストあとで、ふだんのアクセスができることをチェックします。

きろくには、「ふだんのページはひらけたか」「ブロックページはでたか」「あうイベントはあったか」のみっつをのこします。どれかがくいちがうなら、けっかはほりゅうにします。

## 7. みじかいしっぱいケースでチェックのしかたをつかむ

たとえば、テスト URL でタイムアウトし、アタックリストにもイベントがないケースです。このとき「こうげきがとまった」とはいいきれません。

まずふだんのページをひらきなおします。それもタイムアウトするなら、なまえかいけつ、リスナーポート、アップストリームのセットをしらべます。ふだんのページがもどったあとで、SafeLine をとおるホストネームからテストをやりなおし、ブロックページとイベントをセットでチェックします。

このテストでいえるのは、きろくしたセットアップとけいろで、そのテストリクエストがブロックされたということです。すべてのコードインジェクション、エンコード、エンドポイント、べつのアクセスけいろまでふせげることをしめすものではありません。URL、じこく、ふだんのレスポンス、ブロックページ、イベントのないようをそろえ、たしかめられたはんいをそのままきろくしてください。
