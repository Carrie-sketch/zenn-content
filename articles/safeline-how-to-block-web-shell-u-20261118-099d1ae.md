ファイルアップロードフォームをまもるには、あやしいリクエストをとめるだけではたりません。「なにをうけいれるか」「どこへほぞんするか」「ほぞんしたものをサーバーがじっこうできるか」を、アプリとインフラのりょうほうでかくにんします。

web shellは、HTTPリクエストをとおしてアプリのきのうやコマンドじっこうをあやつる、こうげきしゃのスクリプトです。アップロードのせいこうだけで、じっこうされたとはいえません。ただし、じっこうできるばしょへあやしいファイルがほぞんされたなら、ちょうさがひつようです。

SafeLineは、セルフホストでうごかすリバースプロキシがたのWAFです。HTTP/Sトラフィックをフィルタリングし、ドキュメントではコードインジェクション、コマンドインジェクション、パストラバーサルなどへのたいおうがせつめいされています。いっぽう、アップロードされたファイルをもれなくスキャンすることや、すべてのweb shellをけんちすることは、ていじされたしりょうからはほしょうできません。アプリのアップロードせいぎょに、つうしんのぼうぎょをかさねるものとしてつかいます。

## 1. アップロードのいりぐちをあらいだす

まず、ふだんのフォームだけでなく、API、かんりしゃむけのインポート、べつドメインのアップロードきのうもならべます。それぞれについて、つぎのこうもくをメモしてください。

- だれがアップロードできるか
- ひつようなファイルけいしきはなにか
- サイズのじょうげんはいくつか
- ほぞんさきはどこか
- ほぞんごに、どのURLやしくみでとりだせるか

うけいれるかどうかは、アプリがはんだんします。クライアントがつけたMIMEタイプやファイルめいを、そのまましんようしてはいけません。ひつようなけいしきだけをゆるし、ないようもかくにんし、ほぞんめいはサーバーでつくります。けんげんとサイズもチェックし、けいしきをあんぜんにたしかめられないファイルはことわります。

## 2. ほぞんさきでスクリプトがうごかないようにする

できるだけ、アップロードしたデータを、じっこうできるWebディレクトリのそとへほぞんします。はいしんがわでも、そのばしょのファイルがサーバーサイドのインタープリターへわたらないようにせっていしてください。

ダウンロードがひつようなら、アクセスけんをかくにんするしゅとくルートや、てきせつにせいぎょしたストレージをつかいます。ファイルめいをかえるだけでは、ないようはあんぜんになりません。

がぞうなら、メンテナンスされているライブラリでデコードしてから、ゆるしたけいしきへエンコードしなおすほうほうもけんとうできます。アーカイブをてんかいするなら、てんかいのじょうげんと、ほぞんさきからはみだすパスのチェックをもうけます。

## 3. SafeLineをじゅんびする

せんようの、てきせつにほごされたLinuxホストをじゅんびします。ていじされたインストールガイドでは、Docker 20.10.14いこう、Docker Compose 2.0.0いこう、さいしょうリソースとしてCPU 1コア、メモリー1 GB、ディスク5 GBがあげられています。ホストをえらぶまえに、げんこうガイドのアーキテクチャとCPUのようけんもかくにんします。

インストールは、こうしきドキュメント https://docs.waf.chaitin.com/en/home から、げんこうのてじゅんにそってすすめてください。ダッシュボードは `https://<ip>:9443` です。かんりしゃのにんしょうじょうほうをしゅとくするコマンドとして、`docker exec safeline-mgt resetadmin` があんないされています。コンソールへのアクセスとにんしょうじょうほうは、かんりようのしさんとしてほごします。

## 4. アプリへのつうしんをSafeLineへとおす

コンソールの `Applications` から `Add Application` をひらき、アプリのドメイン、リッスンポート、アップストリームのアドレスをせっていします。HTTPSなら `SSL` のオプションをえらび、ひつようなせっていをおこないます。アプリのドメインがSafeLineサーバーのIPアドレスをむくようにします。

ここで、WAFをうかいできないかもかくにんします。オリジンサーバーへのちょくせつアクセス、べつのホストめい、アップロードせんようAPIのドメインをしらべてください。こうかいクライアントがアップストリームへちょくせつとどかないよう、こうせいにあわせたネットワークせいげんをもうけます。

## 5. むがいなテストで、レスポンスとほぞんけっかをたしかめる

きょかされたステージングかんきょうで、じっこうするコードをふくまないテストファイルをつかいます。つぎのケースを、ひとつずつためしてください。

- ゆるされたけいしきのファイル
- ゆるされていないかくちょうしのファイル
- せんげんしたMIMEタイプと、ないようがあわないファイル
- サイズのじょうげんをこえるファイル
- ディレクトリをしめすパスをふくむファイルめい

HTTPレスポンスだけでごうかくにしないことがたいせつです。きょひされたリクエストでファイルがのこっていないか、のこったファイルへアクセスできないかまでたしかめます。

SafeLineのこうげきいちらんと、こべつのしょうさいを、アプリ、リバースプロキシ、ストレージのログとつきあわせます。ドキュメントのこうげきテストは、いっぱんてきなWAFのブロックをしめすもので、multipartアップロードのかんぜんなけんさをしょうめいするものではありません。

### みじかいしっぱいれい

たとえば、かくちょうしでのきょひはせいこうしたのに、アプリがけんさよりさきにファイルをこうかいディレクトリへほぞんしていたとします。がめんにはエラーがでても、ファイルはURLからとりだせるままです。このケースでは、きょひのレスポンスだけをみたテストでは、もんだいをみのがします。ほぞんのタイミングと、きょひしたときのあとしまつもかくにんします。

せいじょうなアップロードがとまったときも、まずWAFとアプリのきろくをつきあわせ、どのそうがきょひしたかをしらべます。げんいんになったせいぎょだけをせまくちょうせいし、せいじょうケースときょひすべきケースをもういちどためしてから、ほんばんへはんえいします。

## 6. あやしいほぞんがあったら、じっこうのこんせきをしらべる

アップロードのじこくと、そのあとにアップロードさきへきたリクエストをつきあわせます。よそうしないスクリプト、アプリのワーカープロセスからうまれたふしんなこプロセス、ふだんとちがうそとむきのせつぞくも、ちょうさのてがかりです。

ひとつのブロックきろくがあっても、それよりまえのアップロードがしっぱいしたとはいえません。あやしいファイルがほぞんされていたら、アクセスできたか、じっこうできたかをかくにんします。じっこうがうたがわれるなら、ログとファイルをほぜんし、えいきょうをうけたワークロードへのアクセスをせいげんして、インシデントたいおうのてじゅんへすすみます。

ふっきのまえには、アップロードのけんさやじっこうせっていのよわさをなおします。こうげきしゃがべつのアクセスしゅだんをのこしているかもしれないため、あやしいファイルをひとつけすだけでたいおうをおえないでください。
