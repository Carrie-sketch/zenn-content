インターネットにさらしているWebアプリは、ランサムウェアにつながるさいしょのいりぐちになりえます。ふるいエンドポイントへのこうげき、ぬすまれたアカウントでのログイン、アップロードされたWebシェル。はじまりは、ログインページへのアクセスがすこしふえるだけかもしれません。

ここでめざすのは「WAFをいれたからあんしん」というじょうたいではありません。HTTP/Sリクエストがかならずチェックをとおること、うらぐちからアプリへアクセスできないこと、すでにしんにゅうされていないかをしらべること。このみっつを、テストとログでたしかめます。

SafeLineは、セルフホストでうごかすリバースプロキシがたのWAFです。HTTP/Sトラフィックをフィルタリングし、モニタリングします。ドキュメントではSQLインジェクション、コマンドインジェクション、パストラバーサル、ブルートフォースなどへのたいおうがせつめいされています。ただし、ランサムウェアをかならずふせぐものではなく、パッチやインシデントたいおうもひつようです。

## 1. まもるアプリと、あやしいサインをかきだす

まず、つぎのチェックリストをうめます。

- こうかいホストめいとポート
- オリジンサーバーのIPアドレス
- ログイン、アップロード、かんりページ、APIのパス
- きんきゅうパッチをあてるたんとうしゃ
- サーバーをネットワークからきりはなせるたんとうしゃ

あわせて、アプリのアクセスログ、ログインのきろく、アップロードさきのファイルをみます。みおぼえのないじっこうファイル、ふしんなプロセス、せつめいできないそとむきのつうしんがあれば、WAFのセットアップとへいこうしてインシデントたいおうをはじめます。これからのリクエストをとめても、すでにおかれたWebシェルはきえません。

## 2. インストールまえにホストをチェックする

もとのガイドにあるようけんは、Linux、Docker 20.10.14いこう、Docker Compose 2.0.0いこうです。さいしょうリソースはCPU 1コア、メモリ1GB、ディスク5GBで、SSSE3もようけんにふくまれます。ARMにはエディションによるせいやくがあるため、ホストをきめるまえにドキュメントをたしかめてください。

```bash
uname -m
docker version
docker compose version
free -h
df -h
lscpu | grep ssse3
```

このすうちは、ほんばんのトラフィックをさばけることのほしょうではありません。アクセスりょうやログをあつかううんようにあわせて、よゆうをもたせます。

インストールは、こうしきドキュメント https://docs.waf.chaitin.com/en/home から、げんざいのてじゅんをたどります。じどうインストーラーにはrootけんげんがひつようです。てどうでおこなうばあいも、かんきょうへんすう、シークレット、ファイルのパーミッションまでふくめたてじゅんをつかいます。

## 3. ダッシュボードへのアクセスをしぼる

SafeLineのダッシュボードは `https://<ip>:9443` です。かんりしゃアカウントのじょうほうは、つぎのコマンドでとりだします。

```bash
docker exec safeline-mgt resetadmin
```

クレデンシャルはあんぜんなばしょにほかんします。ネットワークのアクセスせいぎょをつかい、かんりようポートへだれでもアクセスできるじょうたいをさけてください。ほんばんのけいろをきりかえるまえに、うんようたんとうしゃがサインインできることもたしかめます。

## 4. アプリをとうろくし、オリジンへのちょくせつアクセスをふさぐ

コンソールの **Applications** から **Add Application** をひらき、ドメイン、SafeLineがまちうけるポート、アップストリームのアドレスをせっていします。HTTPSならSSLのオプションと、ひつようなせっていをおこないます。そのあと、アプリのDNSレコードをSafeLineサーバーへむけます。

ここでおわらせないことがだいじです。インフラのファイアウォールなどで、オリジンのアプリようポートへのアクセスを、そうていしたプロキシけいろとひつようなシステムにしぼります。これはインフラがわでおこなうさぎょうです。

そとのネットワークから、ふるいIPアドレスやべつのホストめいでもアプリにとどかないかテストします。HTTPSではホストめいによってうごきがかわるため、ブラウザーでIPをひらけないだけでチェックかんりょうにしないでください。

### みじかいしっぱいれい

たとえば、DNSだけをSafeLineへむけ、ふるいオリジンの443ポートをあけたままにしたとします。いつものURLではブロックされても、こうげきしゃがオリジンへちょくせつアクセスすれば、WAFをとおらないけいろがのこります。きりかえのかんりょうじょうけんには、DNSだけでなく、オリジンのアクセスせいぎょとそとからのテストもいれます。

## 5. ふつうのそうさとブロックをセットでためす

まず、トップページ、ログイン、アップロード、APIがいつもどおりうごくかをたしかめます。そのあと、じぶんがかんりし、テストをきょかされたアプリで、ドキュメントにあるSQLインジェクションやパストラバーサルのテストをおこないます。

- ブロックページがでるか
- こうげきリストとくわしいじょうほうにテストがのこるか
- テストのじこくとリクエストが、アプリのログとつきあうか
- ブロックされたリクエストで、アプリがわのしょりがじっこうされていないか

ブロックけんすうがふえたことだけで、せいこうとはしません。せいじょうなアップロードがとまる、APIクライアントだけしっぱいする、といったずれもなおします。

SafeLineにはIPベースのレートせいげんやCAPTCHAもあります。ログインへのくりかえしアクセスにはけんとうできますが、おなじIPをつかうユーザーや、ブラウザーをつかわないAPIクライアントへのえいきょうをテストしてください。

## 6. ログから、パッチとインシデントたいおうにつなげる

あやしいアクセスをみつけたら、ねらわれたパス、かんれんするコンポーネント、そのバージョンをしらべます。WAFをいれるまえに、おなじようなリクエストがアプリへとどいていなかったかもたどります。

ブロックされたスキャンがつづくなら、こうかいはんいとぜいじゃくせいをみなおします。ふしんなログインせいこうがあれば、アカウントをしらべ、セッションをむこうにします。Webシェルやコマンドじっこうのあとがあれば、しょうこをほぜんし、ひがいをひろげないためのかくりとインシデントたいおうをすすめます。

あたらしいぜいじゃくせいがでたときも、WAFのこうげきカテゴリだけでまもれるときめつけないでください。えいきょうするバージョンをたしかめ、ベンダーのたいさくをてきようし、きょかされたテストとログでたしかめます。SafeLineのうんようでは、ブロックのかくにんと、アプリそのもののしゅうせいをつづけることがだいじです。
