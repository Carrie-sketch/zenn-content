ログインページのかたちがかわっても、LLMをつかったボットは、ページをよみ、フォームのそうさをなおしながらアクセスをつづけることがあります。ただし、こうしたアクセスでも、ねらいはぬすんだIDとパスワードでログインし、セッションをあくようすることかもしれません。

「how to detect llm driven bot traffic on a login page」をしらべるなら、まず、LLMをつかっているかどうかと、ログインがあくようされているかどうかをわけてかんがえましょう。HTTPリクエストだけでLLMのかんよをたしかめるのはむずかしく、ここであつかうSafeLineのドキュメントにも、LLMをとくていするしくみはしめされていません。

このガイドでは、SafeLineでのチェックと、アプリのログをくみあわせて、クレデンシャルスタッフィングやアカウントののっとりをしらべます。

## 1. ログインのせいこうを、どこでたしかめるかきめる

まず、ログインページ、IDとパスワードのおくりさき、パスワードのリセット、モバイルアプリのにんしょうAPIをあらいだします。そのうえで、ログインのせいこうとしっぱいをきめているサービスをたしかめます。

HTTPステータスが200でも、ログインできたとはかぎりません。パスワードがちがうときにも200をかえすアプリがあるためです。

アプリのログには、じこく、リクエストID、にんしょうのせいこうとしっぱい、プライバシーにはいりょしたアカウントのしきべつしをのこします。パスワード、セッショントークン、にんしょうデータのまるごとのほぞんはさけてください。

ふだんのリクエストすうとしっぱいのわりあいをしらべてから、アラートやせいげんのめやすをきめます。ひとつのIPからたくさんのアカウントへアクセスしていないか、たくさんのIPからひとつのアカウントがねらわれていないかもチェックします。

## 2. SafeLineをおくホストをチェックする

SafeLineは、アプリのまえにリバースプロキシとしておき、HTTPトラフィックをフィルタリング、モニタリングするセルフホストのWAFです。ドキュメントには、IPベースのレートせいげんやCAPTCHAチャレンジがしめされています。これらがあることと、LLMをみわけられることはべつです。

セットアップまえに、Linux x86_64、Docker 20.10.14いこう、Docker Compose 2.0.0いこうをチェックします。ドキュメントのさいしょうスペックは、CPUが1コア、メモリが1 GB、ディスクが5 GBです。CPUのSSSE3についてもチェックしてください。

```bash
uname -m
docker version
docker compose version
free -h
df -h
lscpu | grep ssse3
```

インストールはこうしきドキュメントのてじゅんにそってすすめます。じどうインストールにはrootがひつようなので、じっこうまえにてじゅんをよんでください。

ダッシュボードは `https://<ip>:9443` です。かんりしゃのログインじょうほうは、ドキュメントにあるつぎのコマンドでとりだします。

```bash
docker exec safeline-mgt resetadmin
```

ダッシュボードへのアクセスは、そしきのかんりアクセスのルールにあわせてせいげんします。

## 3. ログインアプリをプロキシのうしろにおく

コンソールで **Applications** をひらき、**Add Application** からドメイン、リッスンポート、アップストリームのアドレスをいれます。HTTPSのアプリではSSLのオプションをえらび、ドメインがSafeLineサーバーのIPをむくようにします。

ほんばんをきりかえるまえに、ただしいパスワードでのログイン、まちがったパスワード、MFA、パスワードのリセット、ログアウトをテストしてください。リダイレクトやCookieが、プロキシをとおしてもただしくはたらくかをみます。

オリジンサーバーへちょくせつアクセスできると、プロキシのせいげんをうかいされるおそれがあります。こうせいがゆるすなら、オリジンへのアクセスを、よていしたプロキシのけいろにしぼります。また、クライアントIPがどのようにつたわるかをたしかめてから、IPごとのせいげんをつかいましょう。

## 4. SafeLineのひょうじとアプリのログをつきあわせる

SafeLineのこうげきリストと **detail** ビューでは、けんちされたこうげきリクエストをしらべられます。ただし、そこにアカウントごとのログインけっかがすべてのこるとは、ドキュメントからはいえません。

ログでつかえるじこくやリクエストIDをてがかりに、プロキシでみえたアクセスと、アプリのにんしょうけっかをつきあわせます。くりかえすしっぱい、たくさんのアカウントへのアクセス、しっぱいのあとにおきたふしんなせいこうをさがしてください。

ブラウザーをあやつるボットは、JavaScriptをうごかし、リダイレクトをたどることもあります。もっともらしいUser-Agentやページのたどりかただけでは、あんぜんとはいえません。いっぽう、パスワードマネージャーやアクセシビリティツール、オフィスのきょうゆうIPを、ざつなルールでボットあつかいしないようにします。

## 5. ちいさなテストでせいげんのききかたをみる

じぶんたちがテストをゆるされたアカウントで、かいすうをしぼったログインしっぱいをおこします。SafeLineとアプリのそれぞれに、なにがのこるか、えらんだせいげんがいつはたらくかをたしかめます。そのあと、ふつうのログインとパスワードのリセットをためし、りようしゃへのえいきょうもみてください。

エンドポイントごとのせっていや、アカウントをみてはんだんするルールのつくりかたは、ここであつかうドキュメントではしめされていません。インストールしたバージョンでつかえるせいげんをたしかめてから、うんようをきめます。

### みじかいしっぱいれい

IPごとのリクエストすうだけをみて、しきいちをこえていないからだいじょうぶ、としてしまうケースです。アクセスもとがぶんさんすると、ひとつひとつのIPはすくないリクエストでも、おなじアカウントにしっぱいがあつまることがあります。

このケースでは、IPごとのすうにくわえ、アカウントごとのしっぱいと、そのあとのせいこうをつきあわせます。CAPTCHAをとおったことも、そのアカウントのもちぬしであるしょうこにはなりません。

## 6. あくようのしょうこにあわせてたいおうする

たんじかんにしっぱいがふえるなら、レートせいげんをけんとうします。たくさんのアクセスもとからひとつのアカウントがねらわれているなら、アプリがわのアカウントほごとMFAをみなおします。

ふしんなログインせいこうがあれば、セッションをしらべ、ひつようにおうじてセッションのむこうかやアカウントのふっきゅうをすすめます。ブロックしたリクエストすうだけであんぜんをはんだんせず、にんしょうのけっかと、そのあとにおきたアカウントのへんこうもたしかめてください。

ちょうさのきろくには、かくにんできたじどうアクセスやにんしょうのあくようと、LLMをつかったかもしれないというすいそくを、わけてのこしましょう。
