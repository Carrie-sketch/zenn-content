ホストへのつうしんをしらべる API が、うけとった `host` を OS のユーティリティーにわたしているとします。ここでアプリがシェルのコマンドをもじれつのれんけつでつくっていると、ホストめいにつづけたシェルのこうぶんまでうごくおそれがあります。サポートのためのちいさな API も、ランサムウェアや Web シェルのしんにゅうぐちになりえます。

このガイドでは、SafeLine を HTTP リクエストのチェックポイントにしながら、アプリとホストのログをつきあわせるてじゅんをまとめます。ねらいは、あやしいパラメーターをみつけることと、コマンドがじっさいにうごいたかをたしかめることです。このふたつは、わけてはんだんします。

## 1. OS コマンドにつながるパラメーターをたなあらいする

まず、しんだん、アーカイブのさくせい、ファイルのへんかん、バックアップ、メンテナンスをおこなうエンドポイントをひろいます。クエリーだけでなく、リクエストボディーもチェックしてください。

- `host`、`filename`、`path`、`options` などのねうちが、どのコードへわたるか。
- そのねうちを、シェルにつたえるコマンドへれんけつしていないか。
- シェルをつかわず、ひきすうをべつべつにわたせるプロセス API やライブラリーへおきかえられるか。
- ホストめいならホストめい、ファイルならゆるされたファイルというように、いみにそったチェックがあるか。

パラメーターのなまえだけであんぜんとはいえません。エンドポイントごとに、たんとうしゃ、アプリのログ、ホストのログ、ちょうさできるじかんのはんいもメモします。

## 2. SafeLine のどうにゅうじょうけんをたしかめる

どうにゅうさきは x86_64 の Linux ホストをきほんに、Docker 20.10.14 いこう、Docker Compose 2.0.0 いこうをよういします。ドキュメントのさいしょうようけんは CPU 1 コア、メモリー 1 GB、ディスク 5 GB です。CPU の SSSE3 へのたいおうもチェックしてください。これらはインストールのさいしょうようけんなので、ほんばんのリソースはトラフィックにあわせてみつもります。

じどうインストールには root のけんげんがひつようです。てじゅんをよみ、そしきのソフトウェアどうにゅうルールにそってすすめます。ダッシュボードは `https://<ip>:9443` です。かんりしゃのにんしょうじょうほうは、ドキュメントにある `docker exec safeline-mgt resetadmin` でしゅとくします。

## 3. アプリへのリクエストが SafeLine をとおるようにする

コンソールの `Applications` から `Add Application` をひらき、ドメイン、SafeLine がまちうけるポート、アップストリームのアドレスをせっていします。HTTPS なら SSL のオプションをえらび、アプリのドメインが SafeLine サーバーの IP アドレスをひくようにします。

つづいて、ふつうのリクエストがただしいアプリへとどくことをたしかめます。あわせて、オリジンへちょくせつアクセスできないかをネットワークのせっていでチェックしてください。オリジンがこうかいされたままだと、SafeLine をとおらないけいろがのこります。

## 4. テストまえに、ひかくできるきろくをそろえる

せいじょうなリクエストをひとつほぞんし、メソッド、エンドポイント、パラメーターめい、Content-Type、レスポンスのステータス、じこくをきろくします。これがテストのきじゅんです。

しらべるポイントは、シェルのくぎり、パイプ、コマンドちかんのこうぶん、それらをエンコードしたもじれつです。ただし、くとうてんやきごうだけでこうげきときめないでください。けんさくぶんにあるきごうと、IP アドレスだけをうけつけるフィールドにあるきごうでは、いみがちがいます。

ツールがたいおうしていれば、もとのリクエストとデコードしたひょうじをりょうほうのこします。なんどもデコードしてできたもじれつを、そのままアプリがうけとったものとみなさず、アプリのパースのしかたとつきあわせます。

## 5. ステージングでひとつずつためす

テストは、きょかされたステージングとダミーデータでおこないます。

1. まず、せいじょうなリクエストがとおることをたしかめます。
2. ひとつのパラメーターだけをかえ、かんりされたテストケースをおくります。
3. ブロックのページがでるかをチェックします。
4. SafeLine のこうげきリストをひらき、`detail` でそのリクエストをしらべます。
5. おなじじこくのアプリのログと、りようできるホストのログをつきあわせます。

データをこわすコマンド、そとへのコールバック、ひみつのじょうほうをとりだすテストはつかいません。SafeLine のドキュメントには OS コマンドインジェクションへのぼうぎょがしめされていますが、あらゆるエンコード、リクエストけいしき、シェルでのけんちをほしょうするものとしてあつかわないでください。

## 6. しっぱいれいから、はんだんのしかたをそろえる

たとえば、ステージングであやしい `host` をおくったところ、HTTP 200 がかえったため「もんだいなし」としてしまったケースです。あとからアプリのログとホストのプロセスをしらべると、アプリがよていしていないコマンドをきどうしていた、というみおとしがありえます。

このしっぱいのポイントは、HTTP ステータスだけでじっこうのうむをきめたことです。とおったリクエストは、ついかのちょうさがひつようです。ブロックされたリクエストについても、わかるのは、そのテストケースがさえぎられたことまでです。

## 7. ほんばんのアラートをたいおうにつなげる

あやしいパラメーターは、こころみのてがかりです。アプリがいとしないコマンドをきどうしたことを、じこくやエンドポイントとむすびつけてたしかめられれば、じっこうをうらづける、よりつよいしょうこになります。

よていしないこプロセス、アプリのアカウントによるファイルのかきこみ、ふだんとちがうそとむきつうしんをチェックします。じっこうがうたがわれるなら、しょうこをほぞんし、そしきのインシデントたいおうへつなげます。しんにゅうごものこるしくみや、ろうえいしたおそれのあるにんしょうじょうほうも、ちょうさのたいしょうです。

ブロックできたときも、かんれんするリクエスト、これよりまえのこころみ、オリジンへのちょくせつアクセスをしらべてください。アプリのあぶないシェルれんけつをなおし、こうげきケースとせいじょうなそうさのりょうほうをさいテストするところまでを、たいおうのてじゅんにくみこみます。
