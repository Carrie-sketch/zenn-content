ペネトレーションテストで「WAF をバイパスできた」といわれたら、まずリクエストがどこをとおり、アプリでなにがおきたかをたしかめます。HTTP 200 がかえっただけでは、エクスプロイトがせいこうしたとはいえません。アクセスできないはずのデータがよめたのか、ファイルをとりだせたのか。テスターとごういした、めにみえるけっかをきじゅんにします。

SafeLine は HTTP/HTTPS のリバースプロキシとしてリクエストをうけとり、せっていされたアップストリームへわたします。そのため、けんちのせっていだけでなく、アプリまでのみちすじをしらべることがたいせつです。WAF によるいちじてきなふうじこめと、アプリそのもののしゅうせいは、べつのタスクとしてすすめましょう。

## 1. さいげんできるリクエストをそろえる

テスターから、きょかされたテストのリクエストをうけとります。メソッド、ホストめい、パス、ヘッダー、Content-Type、ボディーをそろえ、せつぞくさき IP、じこく、レスポンス、アプリでおきたこともひかえます。きょうゆうするデータからは、パスワード、トークン、こじんをとくていできるデータをとりのぞきます。

おなじエンドポイントにたいする、せいじょうなリクエストもほぞんしてください。あとで「こうげきはとまるが、ふつうのそうさはできる」とたしかめるための、ひかくのきじゅんになります。

## 2. WAF をとおったかをたどる

こうかいホストめい、ロードバランサー、SafeLine、オリジンまでをならべます。べつのホストめい、こうかいされたオリジン IP、IPv6、ついかのポートもわすれずにしらべます。

テスターがせつぞくした IP と、そうていしているけいろをくらべてください。オリジンへちょくせつとどいていたなら、まずそのアクセスをふさぎます。SafeLine をとおっていたなら、テストじこくをてがかりに WAF とアプリのログをつきあわせます。WAF にきろくがないことだけで、けんちのふぐあいとはきめられません。けいろとログのとれるはんいを、どちらもたしかめます。

### みじかいしっぱいれい

メインのホストめいではこうげきをブロックできたため、たんとうしゃはたいおうずみとしました。しかし、オリジン IP にアプリの Host ヘッダーをつけると、おなじエクスプロイトがせいこうしました。DNS のむきさきをかえただけでは、オリジンへのちょくせつアクセスはふさげません。このれいでは、けんちのちょうせいよりも、オリジンのアクセスせいげんがさきです。

## 3. SafeLine のせっていときりもどしをじゅんびする

すでに SafeLine があるなら、さいインストールをかんがえるまえに、アプリのせっていをたしかめます。いまのせっていをほぞんし、ほんばんのけいろをかえるまえに、きりもどしのてじゅんをきめてください。

あたらしくどうにゅうするなら、Linux、Docker 20.10.14 いこう、Docker Compose 2.0.0 いこうをチェックします。さいていリソースは CPU 1 コア、メモリー 1 GB、ディスク 5 GB です。これだけでじゅうぶんとはきめず、アーキテクチャーと CPU のようけんもふくめ、[こうしきドキュメント](https://docs.waf.chaitin.com/en/home)のてじゅんをたしかめます。シークレットのあつかいも、そのてじゅんにしたがいます。

## 4. アプリまでのけいろをせっていする

SafeLine のダッシュボードは `https://<ip>:9443` です。`<ip>` を SafeLine サーバーの IP におきかえてアクセスします。

`Applications` から `Add Application` をひらき、ドメイン、まちうけポート、アップストリームのアドレスをせっていします。HTTPS のアプリでは SSL のオプションをえらびます。アプリのドメインが SafeLine サーバーの IP をさすように DNS もせっていしてください。

アップストリームが、ねらったアプリとかんきょうをさしていることをチェックします。そのあと、ページのひょうじ、ログイン、たいしょう API のせいじょうなそうさをためします。

## 5. オリジンへのちょくせつアクセスをせいげんする

オリジンのファイアウォールやネットワークのアクセスせいぎょで、アプリへのつうしんが、いとしたプロキシのけいろからくるようにします。ヘルスチェック、かんりようのせつぞく、ほかのひつようなつうしんをあらいだしてから、せいげんをかけてください。これはインフラがわのさぎょうです。SafeLine がオリジンのファイアウォールをじどうでかえるとはかんがえません。

そとからのネットワークで、オリジン IP へのアクセスをためします。アプリのホストめいをつけたリクエストでも、うかいできないことをたしかめます。じっさいにこうかいされている IPv4、IPv6、べつのポートがチェックのたいしょうです。

## 6. けんさをとおったこうげきはアプリのかいしゃくとくらべる

いとした WAF のけいろをとおってもせいこうするなら、リクエストのエンコード、おなじなまえのパラメーター、Content-Type、エンドポイントのアクセスけんげんをしらべます。WAF のけんちと、アプリのロジックのもんだいをきりわけるためです。

SafeLine には Web こうげきへのぼうぎょ、IP ベースのレートせいげん、アクセスせいぎょがドキュメントにきさいされています。いまのデプロイでつかえるものから、じっさいのこうげきにあうたいおうをえらびます。レートせいげんでくりかえしのこころみをおさえても、ひとつのリクエストでつけるあなはなおりません。

ぜいじゃくなコンポーネントやアプリのロジックをしゅうせいします。すぐになおせないときは、たんとうしゃがしゅうせいするまで、たいしょうエンドポイントのアクセスせいげんをけんとうします。ドキュメントにないカスタムルールやれんけいを、つかえるものとしてあてにしないでください。

## 7. さいテストできたことをきろくする

もとのきょかされたテストと、ごういしたすくうのバリエーションをさいじっこうします。せいじょうなリクエストもくりかえします。ブロックページだけでなく、もとのこうげきのもくてきがたっせいされないことを、アプリがわでもたしかめてください。

SafeLine のコンソールでは、こうげきリストからくわしいないようをひらけます。がいとうするきろくがあれば、オリジンのログやアプリのけっかとあわせて、さいテストのしょうせきにします。

たいおうをとじるときは、もとのさいげんリクエスト、けいろやアプリのへんこう、ちょくせつアクセスのチェック、せいじょうなそうさ、さいテストのけっかをのこします。テスターの IP だけをブロックしても、べつの IP やけいろからのせいこうはふせげたといえません。いちじてきなふうじこめと、まだのこっているアプリのしゅうせいを、はっきりわけてきろくしましょう。
